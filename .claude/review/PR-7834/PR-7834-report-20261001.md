## Findings

### Blocking (must fix)

- **컬렉션 사이클 누락** - `src/query/query_executor.c:19767`에서 컬렉션을 복원한 해시는 `disk_size == 0`인 메모리 표현을 사용하지만 자식 스캔의 `PEEK` (튜플 데이터를 복사하지 않고 참조하는 읽기) 값은 디스크 표현을 사용하므로, 같은 `SEQUENCE OF INTEGER` 값 `{-1}`도 해시가 달라져 루트와의 정확 비교를 건너뛰고 `NOCYCLE` 결과에 사이클 행을 추가합니다.

```c
copy = pr_is_set_type (type); /* query_executor.c:19754 */
pr_type_p->data_readval (&buf, &dbval, domp, -1, copy, NULL, 0); /* :19767 */
col_hash = mht_get_hash_number (UINT_MAX, &dbval); /* :19772 */
```

  근거: `object_primitive.c:7205`는 `copy=true`에서 컬렉션을 복원하고, `set_object.c:1959,6265`의 새 참조는 `disk_size=0`; 반면 `object_primitive.c:7273`의 `copy=false`는 `disk_set`/`disk_size`를 유지하며 `memory_hash.c:2494`는 이 디스크 바이트만 해시합니다.
  경로: `scan_manager.c:8971`의 자식 값 읽기 -> `query_executor.c:18319`의 해시 -> `18322,18327`의 해시 일치 조건 -> 정확 비교.
  확인용 SQL (미실행, 소스상 예상: develop은 루트 한 행, PR은 같은 행을 LEVEL 2에도 출력):

```sql
CREATE TABLE cb_t (id INT, pid INT, s SEQUENCE OF INTEGER);
CREATE TABLE cb_u (n INT);
INSERT INTO cb_t VALUES (1, 1, {-1});
INSERT INTO cb_u VALUES (1);
SELECT t.id, t.s, LEVEL, CONNECT_BY_ISCYCLE FROM cb_t t, cb_u u
START WITH t.id = 1 CONNECT BY NOCYCLE PRIOR t.id = t.pid;
```

- **형제 튜플의 스필 누락** - `src/query/query_executor.c:18386`의 스필 호출은 증가한 `children`을 넘기지 않고 부모의 자식 스캔이 끝난 뒤에야 이를 `stack`으로 옮기므로, 루트 하나에 큰 튜플의 자식이 다수인 질의는 `max_connect_by_dfs_size=0` 또는 8MB에서도 전체 자식 튜플을 메모리에 보관하여 OOM으로 실패할 수 있습니다.

```c
children_count++; /* query_executor.c:18383 */
spill.mem += tpl_len;
qexec_connect_by_spill_if_needed (thread_p, &spill, stack, stack_count, path, node.level - 1);
```

  근거: `query_executor.c:20067,20090`에서 빈 스택과 `path_top=0`인 루트는 아무 튜플도 내리지 못하고 종료하며, 자식의 스택 이관은 `18466`에서 스캔 종료 후 수행합니다.
  경계 사례: 부모 한 행의 자식 100,000개가 각각 2KB이면 튜플 본체만 약 195MiB를 먼저 할당합니다 (소스상 계산, 측정값 아님); 기존 구현은 `qexec_insert_tuple_into_list`로 임시 리스트에 기록합니다.
