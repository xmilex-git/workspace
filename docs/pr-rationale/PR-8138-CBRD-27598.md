## 1. 어떤 SQL이 틀렸나

`set trace on` 상태에서, 병렬 heap 스캔이 실행하는 부질의 안에 UNION/EXCEPT/INTERSECT나 해시 조인이 있으면 서버가 SIGSEGV로 죽었습니다.

```sql
create table t_big (a int, b int);
insert into t_big select rownum, rownum from db_class x, db_class y, db_class z, db_class w limit 300000;
create table t_small (a int primary key, b int);
insert into t_small values (1, 1), (2, 2), (3, 3);
commit;

set trace on;
-- 부질의 안에 UNION ALL (비상관)
select count(*) from t_big where b > (select max (u.v) from (select b v from t_small union all select 0 from db_root) u);
-- 부질의 안에 해시 조인 (상관)
select count(*) from t_big where a <= 10 and b > (select /*+ use_hash */ max (z.b) from t_small z, t_small y where z.a = y.a and z.a = mod (t_big.a, 3) + 1);
```

trace를 끄거나 `NO_PARALLEL_SCAN`을 주면 정상입니다. 재현에 쓴 12가지 모양 중 UNION, DIFFERENCE, INTERSECTION, HASHJOIN을 쓴 것은 pre 빌드(develop `be683e04c`)에서 모두 죽었습니다.

## 2. 원인

- trace를 켠 병렬 heap 스캔에서, 워커는 끝날 때 자기가 실행한 부질의의 trace 통계를 메인 XASL 트리에 합칩니다(`trace_storage_for_sibling_xasl::merge_xasl_tree ()` → `xasl_merge_stats ()`).
- `xasl_merge_stats ()`는 부질의의 모든 XASL 노드를 돌면서(`iterate_xasl_tree`), 노드마다 `spec_list->s_id.scan_stats`를 조건 없이 읽어 합쳤습니다.
- 집합 연산 노드(`UNION_PROC`, `DIFFERENCE_PROC`, `INTERSECTION_PROC`)와 `HASHJOIN_PROC` 노드는 자기 스캔이 없어서 `spec_list`가 `NULL`입니다. 그래서 NULL 역참조로 죽었습니다.

## 3. 고친 방식과 이유

```cpp
/* set operation and hash join nodes have no spec_list */
if (src_node->spec_list != nullptr && dst_node->spec_list != nullptr)
  {
    ... scan_stats, partition_stats 합치기 (기존 코드 그대로) ...
  }
```

- **노드를 통째로 건너뛰지 않고 scan 통계만 감쌌습니다.** 같은 노드의 `xasl_stats`(time, fetch, ioread), `groupby_stats`, `sq_cache`, `memoize_storage`는 `spec_list`와 상관없이 의미가 있습니다. 예를 들어 trace의 `UNION (time: 0, fetch: 24, ...)` 줄은 `xasl_stats`에서 나옵니다. 그래서 `spec_list`를 읽는 부분만 조건 안에 넣고 나머지 합치기는 그대로 둡니다.
- **양쪽(`src_node`, `dst_node`)을 모두 확인합니다.** 둘은 같은 `header.id`의 노드이므로 보통 함께 NULL이지만, 한쪽만 확인하면 다른 쪽이 NULL일 때 다시 죽습니다. 비용은 포인터 비교 하나입니다.
- **diff가 큰 이유.** 기존 scan/partition 통계 코드를 `if` 블록 안으로 옮기면서 들여쓰기가 바뀌었고, 줄 길이 때문에 codestyle이 줄바꿈을 다시 했습니다. 문장 자체는 바꾸지 않았습니다(`/* agl copy needed..? */` 같은 기존 주석도 그대로).
- 주석 한 줄로 왜 `spec_list`가 없을 수 있는지(집합 연산, 해시 조인)를 적었습니다.

## 4. 범위 밖으로 둔 것

- **워커가 실행한 해시 조인 노드의 자체 통계는 합치지 않습니다.** 해시 조인의 BUILD/PROBE 행 수와 method는 `spec_list`가 아니라 해시 조인 전용 통계에 있고, 원래 `xasl_merge_stats`가 합치지 않던 값입니다. 그래서 워커가 실행한 HASHJOIN의 trace 줄은 메인 XASL 노드의 초기값(`method: skip`)을 보여줍니다. 서버가 죽는 문제와는 별개의 trace 정확도 문제라서 PR Remarks에 적고 TC Case 2에 주석과 함께 고정했습니다. 나중에 이 통계를 합치면 Case 2의 답을 바꿔야 합니다.
- **머지 조인(`MERGELIST_PROC`) 부질의는 이 경로에 오지 않습니다.** `px_scan_checker`가 이 경우 바깥 스캔을 `CANNOT_PARALLEL_SCAN`으로 만들기 때문입니다. 재현 m1, m2에서 바깥 스캔이 직렬인 것을 확인했습니다.
- CBRD-27599(#8137, trace 정확도)와 trace-overhead 브랜치는 `xasl_merge_stats`를 건드리지 않습니다. 그래서 이 수정이 따로 필요합니다(trace-overhead 설치본에서도 같은 모양으로 죽는 것을 확인).
