# CAS 통합 논의 자료의 편집 결정

2026-09-05 사용자 검토. 대상: [develop 대비 변경점 논의 자료(md) — CUBRID 개발자 대상 '왜 바뀌어야만 하는지·어떤 코드가'](https://github.com/xmilex-git/workspace/issues/217).

## D1. 본문과 상세 해설의 독해 깊이

- 결정: 본문은 구조 변경의 타당성과 대가를 논의할 수 있게 쓰고, 연결된 상세 절은 주요 코드를 직접 리뷰할 수 있게 작성한다.
- 근거: 사용자 Q1 “추천대로”.
- 편집 결과: 첫 독해에서 상태·프로세스 경계와 선택 이유를 이해하고, 함수 호출·소유권·실제 코드 비교는 필요할 때 펼친다.

## D2. 핵심 선택의 설명 순서

- 결정: 기존 제약 → 선택한 변경 → 다른 방법이 어려운 이유 → 치르는 비용 순서로 설명한다.
- 근거: 사용자 Q2 “좋아”.
- 편집 결과: 이미 확정한 설계를 독자에게 설명한다. 기각된 노선을 다시 결정하는 절차로 만들지 않는다.

## D3. 운영 정책과 CI 상세의 위치

- 결정: 본문에는 개발자가 반드시 알아야 할 의미 변화만 남기고, 항목별 운영 정책 미결과 CI 실패 목록은 부록으로 옮긴다.
- 근거: 사용자 Q3 “추천대로”.
- 편집 결과: 본문의 성능·검증 요약에서도 전체 CI/HA 완료 여부와 측정 한계는 숨기지 않는다.

위 결정은 문서 구성에 대한 합의다. 미결 제품 정책이나 전체 기술 내용에 대한 최종 승인을 의미하지 않는다. 도메인 용어를 새로 정의하지 않았고, 되돌리기 쉬운 편집 결정이므로 공용 용어집·ADR은 추가하지 않는다.
