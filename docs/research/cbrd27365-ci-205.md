### 엔진 버그 11건 — CAS 가 peek 한 리스트 문자열을 C 문자열로 사용
bug_bts_4461/8080/7915/9420/9647/8387/10236/17595/17595_2, cbrd_21755, trac_341/JDBC — 전부 JDBC `DatabaseMetaData.getColumns`.
증상 `Unknown class "dba.blobtesta\tblobtest"` = `"dba.blobtest" "\x01" "a" "\x08" "blobtest"`: 새 포맷에서 다음 컬럼(1B 길이헤더+본문)이 바로 이어짐.
`cas_execute.c fetch_attribute` 가 `db_query_set_copy_tplvalue(result, 0)`(peek) 결과의 `db_get_string()` 을 `db_find_class`/`db_get_attribute` 에 그대로 전달.
구 포맷은 8B 정렬 0 패딩이 NUL 역할(길이가 8 배수면 develop 도 잠재 결함, bf2df_str_compare D-191-1 과 같은 부류).
**수정(D-205-1)**: `cas_copy_peeked_string` 로 NUL 종료 스택 복사(식별자 크기, `er_set` 포함); csql auto-trace `%s` → `%.*s`.
peek 소비자 전수 추적(리뷰어 확인): CAS execute/fetch(net_buf 크기 기반), csql_result(크기 기반), method handler, execute_schema(int) — 나머지 안전.
