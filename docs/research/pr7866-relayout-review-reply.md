재계산 전 기존 레이아웃과 새 레이아웃의 `kind`, `size`, `value_format`, `alignby`를 비교하는 debug 검사를 추가했습니다. 기존 배열을 덮어쓰기 전에 검사하며, NULL/VARIABLE 컬럼은 이전 값이 모두 NULL이라는 계약 아래 타입 확정을 허용합니다. interpolation의 기록 전 타입 변경도 빈 리스트에 한해 허용합니다.

이번 검사는 엔진 내부 불변식을 확인하는 용도로 두고, 검사 루프와 임시 값 전체를 `!NDEBUG`로 제외했습니다. 같은 기준으로 값 기록 경로의 기존 FIXED 폭·DIRECT 인코딩 불일치 검사도 assert로 변경했습니다. 일반적인 크기 계산 실패 처리는 유지합니다.

정상 경로의 인코딩·크기 계산은 유지합니다. 다만 기존 FIXED 폭·DIRECT 인코딩 불변식이 깨지는 경우에는 release에서 더 이상 해당 오류를 반환하지 않습니다. 이 조건들은 debug assert로 검출하는 계약으로 바꿨으며, release에도 실패 시 동작이 완전히 같다는 의미는 아닙니다. 타입별 값 해석의 의미까지 검증하는 것으로 범위를 넓히지는 않았고, 성능 측정은 수행하지 않았습니다.

optdebug/release 빌드와 소형 SQL 스모크를 통과했습니다. 실제 엔진 함수로 기존 NULL 튜플의 타입 확정 후 읽기, 같은 물리 포맷의 도메인 변경 허용, 비호환 변경의 assert 검출을 확인했고, 실제 전처리 결과에서 release 검사 코드가 제외됨을 확인했습니다.
