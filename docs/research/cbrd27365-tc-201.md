## 왜 "입력 확대" 만으로는 전부 복원되지 않았나

test_mode 에서 `parallel_sort/hash_join_page_threshold` 는 0 → 실질 임계 **2 페이지**, 병렬 리스트 스캔은 32 페이지. 이 넷은 행 수/튜플 폭을 키워 복원된다.

해시 in-memory/hybrid 판정은 `slots + entries + payload ≤ limit`(in-memory) / `slots + entries + 12B×rows ≤ limit`(hybrid). all-INT 3~4 컬럼 튜플은 새 포맷에서 16~20B/행이라 payload ≈ 위치 테이블이고, **hybrid 가 선택되는 창이 8M 기본값에서 사실상 사라진다**(예: 100001 행 tbl_b: in-mem 6.29MB, hybrid 5.91MB). 게다가 최적화기 `qo_hjoin_cost` 는 `rows × 52B > 0.8 × limit` 이면 spill 비용을 더해 플랜을 바꾸므로 limit 을 낮춰 hybrid 를 강제하는 길도 막힌다(112k 실험: 플랜이 SPLIT 파티션 해시조인으로 바뀜). 빌드측은 항상 작은 리스트가 선택되므로 빌드 테이블만 넓혀도(t_bigint 실험) 소용없다.
