## 1. 결정과 계측 범위

- 기준 엔진 `cad27172b`, 작업 트리 `/home/cubrid/dev/cubrid-worktree/dpin`. 계측 커밋 [`8764c55ba`](https://github.com/xmilex-git/cubrid/commit/8764c55ba4ed741b1d6009c0b179bb588a4dc780), TC `dpin-tc` [`cef1327c3`](https://github.com/xmilex-git/cubrid-testcases/commit/cef1327c32d3f081dd8d8633ca56515f24efd4f0).
- D-316-2: 동일 계측으로 구현 전후를 비교하기 위해 계측을 먼저 넣는다. SQL 결과·타입 선택·변환 방향은 변경하지 않는다.
- D-317-20: 기존 8종과 `Num_planned_convert`를 등록한다. 비교와 키는 타입 판정·strict 시도를 세며, 계획된 변환기 실행과 구분한다.
- D-324-01: S-29는 분석 SUM/AVG의 non-DISTINCT helper가 VARIABLE/non-normal collation으로 거절되는 경우만 센다. 일반 집계의 이 조건은 해당 없음. 일반 집계의 실제 도메인 확정은 S-23/S-26으로 측정한다.
- S-29와 S-27 등 여러 사건이 같은 행에서 일어날 수 있다. 카운터 합은 고유 행 수가 아니다. S-18/S-20/S-23은 resolver 진입 횟수(재시도 포함)이며, 성공적으로 바뀐 도메인 개수만을 뜻하지 않는다.
- 미래 게이트·계획된 변환기의 기준값은 0이다. `Num_planned_convert=0`은 기존 변환량이 0이라는 뜻이 아니므로 이후 “기존 대비 변환량 증가 없음” 판정의 분모로 사용할 수 없다.
- current-thread가 필요한 기존 helper는 감시 중에만 thread entry를 조회한다. 신규 9종의 세션 합계는 기존 transaction 통계 배열에 원자적으로 더한다. 기존 PX 추적 수집기는 선택된 통계만 합치므로 그대로 사용하면 새 카운터가 누락된다. 이 9종은 추적 여부와 무관하게 워커 사건을 합치며, 다른 카운터의 경로와 SQL 동작은 유지한다. 새 배열·할당·락은 추가하지 않으며, 수집 중에는 기존 전역 atomic에 더해 세션 atomic 비용이 든다.

## 2. S-29 독립 검토

사용자 요청에 따라 Astra가 원 결정·소스 이력·호출 경로를 독립 검토했다. [검토 기록](https://github.com/xmilex-git/workspace/issues/324#issuecomment-5775697586).

두 helper의 도입 커밋 `7749f4ff8`부터 일반 집계의 빠른 경로 조건은 함수·피연산자·DISTINCT·정렬뿐이었다. 인벤토리 최초 커밋 `57ec5eb`이 분석 함수와 동일한 도메인 조건을 잘못 병기했다. 따라서 이번 정정은 타입 정책 변경이나 기준 소스 드리프트에 대한 우회가 아니다. 일반 집계의 누산기 지원 타입·적합성 검사는 여전히 존재하며, S-29 N/A를 모든 타입 검사 부재로 해석하지 않는다.

P3에 분석 `SUM(?) OVER (ORDER BY c_big)`, `AVG(?) OVER (ORDER BY c_big)`를 추가했다. 집계 카운터 합계가 양수라는 사실만으로 S-29 개별 도달을 단정하지 않는다. 별도 디버거 실행에서 `qdata_evaluate_analytic_func` 진입의 `PT_AVG`, `Q_ALL`, `DB_TYPE_VARIABLE`을 관측했다(`scratch/312-324/s29-gdb.log`). 이 진입점에서 helper 호출까지 `func_p`를 변경하지 않으므로 S-29 거절 분기가 성립한다는 런타임 입력 + 정적 경로 증거다. 카운터 증가 명령 자체에 중단점을 건 증거라고 표현하지 않는다. 최초 줄 중단점은 다른 함수로 이동했고, 두 번째 조건부 중단점은 인자 기호를 찾지 못해 둘 다 제외했다. 관측값 0과 별개로 정적 삭제 근거가 필요하다(D-320-04).

## 3. 재현 방법

실행 호스트: Rocky Linux 8.10, Intel Xeon Silver 4216 2.10GHz. 전용 DB `dpin324`, master 1701, broker 36100.

하네스와 데이터 생성 SQL: `/home/cubrid/dev/workspace/.git_ignored_dir/scratch/dpin/bench/`의 `DomainBench.java`, `setup.sql`.

- 10행 시드의 6중 cross join으로 1,000,000행. `c_int=행번호 mod 1000`, `c_big=행번호`, 그룹 100개, 숫자·문자·DATETIME 열 및 `i_int`, `i_str`, `i_grp_int`.
- L=리터럴(auto-param 가능), H==같은 부류 JDBC bind, H≠=다른 부류 bind. L은 H≠와 같은 값을 SQL 리터럴로 표현한다. F7처럼 기준 컬럼 없는 슬롯은 하네스의 same/other 정의를 따른다.
- 셀당 워밍 1회 + 측정 5회. JDBC 결과를 끝까지 소비한다. ms는 execute와 결과 수신을 포함하며 준비·통계 판독은 제외한다. P8은 1,000행 INSERT 100회이며 매 반복 rollback해 데이터가 누적되지 않는다.
- GROUP_CONCAT·분석 함수·UNION 반환량은 `c_big<=10000`, 상관/CTE의 외부 입력은 `<=1000`으로 제한한다. 데이터 테이블 자체는 모두 동일한 100만 행이다.
- 매 반복 `SET @collect_exec_stats=0` → `1`로 초기화, 대상 실행, `0`으로 감시 중지, `SHOW EXEC STATISTICS ALL` 판독. `perfmon_get_stats_and_clear`는 개별 값을 읽으면서 0으로 지우므로 전후 누적값 차감은 사용하지 않는다. 감시를 끄고 읽어 판독 SQL의 자기 계측을 제외한다.
- optdebug 카운터와 release 시간은 서로 다른 목적의 값이다. release/optdebug 간 시간 차이를 성능 회귀로 판정하지 않는다.
- P7은 순차·병렬 모두 실행 추적 OFF로 측정한다. 초기 trace-OFF의 비원자 합산과 trace-ON의 선택적 병합에서 각각 누락을 발견했다. 해당 자료는 `optdebug-p24.trace-off.tsv`, `optdebug-p24.trace-on-unmerged.tsv`로 보존하며 최종 기준선에서 제외한다. 신규 9종의 세션 원자 합산 수정 뒤 P7을 다시 측정한다.
- PMU는 `BENCH_SERVER_PID`, `BENCH_PERF_DIR` 지정 시 해당 전용 서버 프로세스의 `branches:u`, `branch-misses:u`를 워밍 후 5회 묶음으로 기록한다. 통계·트랜잭션 제어와 서버 유휴 동작이 포함된 묶음 총계이며 질의 한 번의 중앙값이 아니다. 시간은 별도로 5회 중앙값·MAD를 기록한다. Linux perf 4.18은 SIGINT로 종료해 결과를 기록한다. SIGTERM으로 종료해 파일이 비었던 첫 release 실행은 `release-p0.sigterm-unflushed.tsv`와 `perf.sigterm-unflushed/`로 보존하고 제외했다. PMU attach 실패·미계측은 0으로 대체하지 않는다.

```bash
javac -cp <install>/jdbc/cubrid_jdbc.jar DomainBench.java
java -cp .:<install>/jdbc/cubrid_jdbc.jar DomainBench <jdbc-url> setup <absolute-setup.sql>
BENCH_PARALLELISM=0 java -cp .:<install>/jdbc/cubrid_jdbc.jar DomainBench <jdbc-url> run
# 전용 서버의 parallelism을 24로 변경하고 재시작한 뒤:
BENCH_PARALLELISM=24 java -cp .:<install>/jdbc/cubrid_jdbc.jar DomainBench <jdbc-url> run
```

`parallelism`은 세션에서 변경할 수 없으므로 서버 설정별로 나누어 실행한다. 0 단계는 75개 셀, 24 단계는 P7의 6개 셀이다. 두 결과를 중복 헤더 없이 합쳐 81개 셀 × 5회로 집계한다.
