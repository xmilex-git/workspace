# 논리 실행 체인은 물리 세션 경계를 넘어 전파된다

> **Superseded (2026-08-24, #108/#109)** — 목적지 축소로 이 결정의 전제가 소멸했다.
> `PARALLEL_ENABLE` SP는 서버측 SQL이 금지되므로(`ER_SP_PARALLEL_ENABLE_NO_SQL`) SP→SQL→SP
> 중첩 자체가 불가능하고, 콜백을 별개 세션에서 실행하는 2단계 helper 프로세스도 폐기됐다.
> 따라서 세션 경계를 넘길 체인이 없다 — px 워커의 SP 실행은 세션 실행 체인에 **불참**하며
> (#108 D108-4), 같은 스레드 인자 중첩의 깊이 15는 `thread_local` 카운터로 유지된다.
> 중첩 직렬 강등(#106)도 함께 소멸. 재론 조건: SQL 포함 SP 병렬화를 다시 목적지에 넣을 때.

javasp 병렬(지도 xmilex-git/workspace#87, 결정 티켓 #91 D7)에서 재귀 깊이 제한(15)과 중첩 직렬 강등 플래그의 적용 단위는 물리 세션이 아니라 **논리 실행 체인**(SP 호출 사슬)이다. 2단계에서 재귀 콜백 SQL은 helper 프로세스의 별개 세션에서 실행되므로, 깊이 카운터와 병렬 문맥(강등) 플래그를 helper 핸드셰이크에 실어 세션 경계 너머로 잇는다. 이렇게 하지 않으면 helper 세션마다 깊이가 0으로 리셋되어 15 제한이 무력화되고(무한 재귀 허용), 직렬 강등(#106) 판정도 근거를 잃는다.

## Consequences

- join-tran 핸드셰이크(#103)의 세션 클로닝 항목에 깊이 카운터·병렬 문맥 플래그가 포함되어야 한다.
- 중첩 직렬 강등의 강제 지점(#106)은 이 플래그를 판정 근거로 쓴다.
- 1단계 funnel에서는 콜백이 리더 세션으로 돌아오므로 별도 전파 없이 funnel 점유 슬롯(K=1)으로 체인 귀속을 판정한다(#91 D6).
