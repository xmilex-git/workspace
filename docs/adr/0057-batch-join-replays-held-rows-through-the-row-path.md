# 배치 조인은 쌓아 둔 바깥 행을 기존 행 경로로 다시 흘려 조인한다

배치 조인(`nl_join_batch`)의 목적은 중첩 루프 안쪽 조회의 힙 페이지를 장치가 한꺼번에 읽게 하는 것이다. 구현은 바깥 행을 쌓으면서 행마다 안쪽 인덱스만 먼저 읽어 OID를 모으고, 배치를 닫을 때 그 OID의 힙 페이지를 OS에 알린 뒤(ADR 0055의 힌트), 쌓은 행을 온 순서대로 지금의 행 단위 조인 경로(`qexec_execute_scan_row`)에 다시 넣는다. 행 경로는 바깥 값이 되돌려진 상태에서, 인덱스 탐색 대신 이미 모은 OID를 받아 시작한다.

사용자 결정(2026-11-11): 이 방식은 두고, 범위는 넓힌다. TPC-H Q9(병렬 스캔 워커 안의 첫 조인 단계)와 Q20(바깥 행마다 도는 상관 부질의의 인덱스 조회)도 빨라져야 한다(MAP D39). 스냅샷이 중첩 문장으로 다시 만들어지는 문장도 그대로 묶고, 앞서 읽은 행의 오류는 받아들인다.

## Considered Options

- **모은 OID를 힙 페이지별로 묶어 한 번에 처리(D19의 원래 문장)**: 페이지당 fix가 한 번으로 줄지만, 조인 행을 바깥 순서로 내려면 조회한 행을 다시 정렬해 둘 자리가 필요하고, memoize 저장, left outer의 NULL 행, 안쪽 data filter, 더 깊은 조인 단계로 넘기는 일을 행 경로 밖에서 다시 구현해야 한다. I/O 동시성은 힌트로 이미 얻으므로(ADR 0055) 남는 이득은 fix 횟수뿐이다. 하지 않았다.
- **행 경로를 그대로 쓰고 OID만 먼저 읽기(채택)**: 조인의 의미(memoize, outer join, 필터, 다음 단계)를 한 줄도 다시 쓰지 않는다. 결과와 순서가 행 단위 조인과 같다는 것(C8)이 "행 경로에 같은 값과 같은 OID를 준다"로 줄어든다.

## Consequences

- 순서는 언제나 바깥 순서다. 자유 순서 모드(D22)는 없다.
- semi, anti, following 조인은 묶지 않는다(D21보다 좁다). 첫 일치에서 멈추는 조인에 키의 OID를 전부 먼저 읽는 것은 따로 따져야 한다.
- OID가 버퍼 하나보다 많은 행은 배치에 걸치지 않고(D35) 행 경로가 직접 읽는다. 그 경로는 자기 OID 버퍼마다 힌트한다(ADR 0055의 읽기 힌트).
- 바깥 스캔과 안쪽 인덱스를 행 단위 조인보다 최대 배치 하나만큼 앞서 읽는다. 일찍 멈추는 질의(LIMIT)에서 그 앞선 행이 내는 오류는 행 단위 조인이라면 나지 않았을 오류다. 배치는 OID 16개에서 시작해 배로 커지므로 앞서 읽는 양은 실제로 쓴 행 수에 비례한다.
- 한 단계의 배치는 윗단계의 현재 행에 대한 바깥 행이 끝나면 닫힌다. 깊은 단계의 배치는 윗단계 한 행의 fan-out만큼만 커진다(D20의 단계 사이 연결은 없다).
- 인덱스 리프 읽기는 그대로 한 번에 하나다. 배치가 동시에 읽게 하는 것은 힙 페이지뿐이다.
- 바깥 행이 스캔을 지날 때 정해지고 조인 행이 나올 때 쓰이는 상태는 배치와 맞지 않는다. 지금 아는 것은 GROUP BY skip의 키 시작 표시이고, 그 경우 첫 스캔은 묶지 않는다.

## 2026-11-11 이후 (MAP D40~D43; CBRD-28033)

- **도입 여부를 검토 중이다.** 사용자는 힌트와 bitmap heap scan이 이미 많은 부분을 줄이므로 배치 조인을 더 생각해 보기로 했다. 구현 이슈는 CBRD-28033이고 다음 버전 대상이다.
- **도입하면 파라미터 없이 기본으로 동작한다.** `nl_join_batch`(기본 no)는 작업 브랜치의 스위치다.
- **병렬 스캔 워커의 첫 조인 단계도 묶는다**(구현됨, `5eb88d442`): 워커가 자기 XASL 복제본의 첫 조인 단계에 배치를 걸고, 자기 행이 끝나면 쌓인 행을 마저 조인한다. Q9 콜드 NVMe 24.3초 -> 18.2초, SATA SSD 45.7초 -> 37.7초.
- **목표 범위**(구현 안 됨): 깊은 단계의 배치가 윗단계 행이 바뀌어도 유지되는 것, 바깥 행마다 도는 상관 부질의의 인덱스 조회, semi와 anti 조인. 첫 스캔에 직접 붙은 상관 부질의와, 상관 부질의가 붙은 단계 아래의 조인 단계는 넣지 않는다.
- **깊은 단계를 넓히는 방법**은 `docs/tla/CBRD-28033/BatchChain`이 정리했다(TLC만): 윗단계 행을 넘어 유지되는 배치는 그 위의 값 목록을 모두 쌓아야 하고, 끝날 때는 위 단계부터 비우며, 재생 뒤에는 배치를 닫을 때의 윗단계 값을 되돌려 놓는다.
- **한계 실측**: 버퍼는 비어 있고 OS 페이지 캐시에는 다 있는 상태(미리 읽기가 닿을 수 있는 가장 빠른 값)에서 Q7 30.4~31.7초, Q20 9.2~9.9초다. 남은 범위를 다 넣어도 Q7은 44.1초에서 최대 30%, Q20은 17.5초에서 최대 45% 준다.
- 힌트만으로는 Q7이 거의 줄지 않는다(71~74초 -> 67~75초). 키 하나에 OID가 적은 조인을 줄이는 것은 배치 조인뿐이다.
