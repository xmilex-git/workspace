# 폴드(PR 7837)는 다음 버전 라인의 시작점에 머지한다

CAS의 SQL 컴파일과 프로토콜 처리를 `cub_server`로 옮기는 폴드는 258개 파일을 바꾸고, develop은 4주마다 그 파일의 34%를 다시 건드린다(merge-base 2026-09-08 이후 95커밋·310파일 중 89파일 겹침, PR은 CONFLICTING). 폴드를 compact하게 만드는 후속 작업은 바로 그 겹치는 파일을 또 건드린다. 그래서 폴드는 "검증이 끝난 뒤"가 아니라 **CI 4종 green·코어 0·perf 비악화**라는 머지 조건을 채우는 즉시, 11.5.0 code freeze 직후 **다음 버전 라인의 시작점**에 넣고, 제품화 과제(#256의 6대 과제)·QA test.md·소크 테스트는 **릴리스 게이트**로 둔다.

## Considered Options

- **feature 브랜치에서 제품 수준 검증 후 머지** — 기각. 머지 비용의 기울기가 양수라 검증이 끝날수록 머지가 어려워진다. 사실상 "하지 않는다"와 같다.
- **cub_cas를 남기고 런타임 플래그로 공존** — 기각. 테스트 매트릭스·운영 표면·보안 경계가 두 벌이 되고, 끄는 시점이 영원히 남는다. PR 7837은 UNIX에서 cub_cas를 제거한다(`broker_config.c`, #116 D1 B4).
- **서버 단독 최적화(U1~U3)로 대체** — 폴드의 대체물이 아니다. 셋은 독립 PR로 먼저 올리고, 폴드의 가치(1-hop, 세션 상태 복제의 선택화, 취소·PL 콜백의 서버 내 종단)와 분리해 센다.

## Consequences

- 머지는 일방향 문이다. 실패 시나리오는 롤백이 아니라 릴리스 연기다.
- CAS 프로세스 크래시(JIRA 2022~ 약 28건 부류)가 서버 치명으로 승격되고, APPL_SERVER_MAX_SIZE 재시작이 주던 누수 사면이 사라진다. 디코더 검증·ASan CTP·퍼징·24h 소크가 그 대가로 게이트에 들어간다.
- 머지 뒤 develop의 모든 PR이 폴드 위에서 동작해야 한다. 엔진 개발자 안내는 `docs/research/cas-fold-engine-developer-guide.md`.
- 용어: `CONTEXT.md`의 "폴드 단독 바닥", "머지 조건 / 릴리스 게이트".
