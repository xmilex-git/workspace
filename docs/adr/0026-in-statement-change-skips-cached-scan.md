# 문장 내 변경이 가능한 문장은 페이지 복사 스캔을 쓰지 않는다 (무효화가 아니라 제외)

페이지 복사 스캔(CBRD-27041)은 페이지에 들어갈 때 만든 복사본에서 나머지 행을 읽는다. 그래서 같은 문장이 SP의 DML이나 시리얼 `NEXT_VALUE`로 아직 읽지 않은 행을 바꾸면 그 변경을 보지 못하고, 답이 행의 페이지 배치에 따라 달라졌다. 기대 의미는 **읽는 시점 의미**로 정했다. 수정 전 COPY 읽기의 답이고, 안쪽 힙 스캔과 힙을 읽는 인덱스 스캔이 지금도 내는 답이다. 키만으로 답하는 커버링 인덱스 읽기는 CBRD-27041 이전부터 미리 모은 키를 돌려주어 이 의미를 어겼는데, 같은 판정으로 함께 맞췄다(사용자 결정 2026-10-11).

이를 위해 다음 두 경우에는 문장을 열 때 페이지 복사 스캔을 끄고 행별 COPY 읽기로 돌아간다.

- 문장 안 어디든 `PARALLEL_ENABLE`이 아닌 SP가 하나라도 있는 경우. 판정 단위는 질의 블록이 아니라 문장 전체다. 상관 하위 질의 안의 SP도, 처음 값을 쓸 때 실행되는 비상관 하위 질의(`XASL_LINK_TO_REGU_VARIABLE`) 안의 SP도 바깥 스캔 도중에 실행되어 그 행을 바꾸기 때문이다.
- 스캔 대상이 MVCC 비적용 클래스(`db_serial` 등)인 경우.

앞의 경우(SP가 있는 문장)는 인덱스 스캔의 커버링 읽기도 끄고 행마다 힙을 읽는다. `FOR UPDATE`가 커버링을 끄는 것과 같은 자리이고, loose index scan은 커버링 읽기 위에서만 동작하므로 함께 꺼진다.

`PARALLEL_ENABLE` SP는 직렬 실행에서도 서버측 SQL이 런타임에 거부되므로 데이터를 바꿀 수 없다. 레거시 메서드는 원본 질의 결과를 다 만든 뒤 실행되므로 스캔 도중 변경 경로가 아니다.

## Considered Options

- **트랜잭션 로그 끝 위치로 복사본 무효화 (2a)**: 기각. 복사할 때 `tdes->tail_lsa`를 기록하고, 다음 행에서 값이 달라졌으면 다시 복사하는 방식이다.
  - 프로토타입 `cb612fef2`가 수정 전 답을 되살리는 것은 실측으로 확인했다. 600행 여러 페이지 질의의 차이는 힙 순서로 전부 설명됐다.
  - 기각 이유 1: 행 루프에 비교가 들어간다.
  - 기각 이유 2: 다른 세션이 바꾸는 비적용 클래스 값을 잡지 못한다.
  - 기각 이유 3: "트랜잭션의 모든 변경은 그 트랜잭션 로그에 남는다"는 보이지 않는 불변식에 정답이 기댄다.
- **페이지 LSA로 그 페이지만 정확히 무효화 (2b)**: 기각. 행마다 실제 페이지를 확인하거나, 힙 변경에서 스캔 캐시로 가는 통지 경로가 필요하다. CBRD-27041이 없앤 행별 비용이 되살아나고, 구현 범위가 가장 크다.
- **문장 시작 시점 의미 (PostgreSQL식 command id)**: 기각. 안쪽 스캔과 인덱스 스캔의 develop 답까지 바뀐다.

## Consequences

- SP가 있는 문장은 읽기만 하는 SP여도 CBRD-27041 이전 비용(행마다 fix·복사·unfix)으로 돌아간다. 다만 행마다 실행되는 PL 호출 비용이 훨씬 커서 묻힐 것으로 본다. 측정값은 CBRD-27590 PR에 기록한다.
- 커버링 읽기를 끄는 비용은 SP가 드물게 실행되는 문장의 큰 직렬 커버링 스캔에서 드러난다. release에서 SP를 한 번 부르고 100만 키를 읽는 질의가 1.68배(PK 순서), 2.94배(힙 순서가 흩어진 보조 인덱스) 느려졌다. 병렬 인덱스 스캔과 SP를 행마다 부르는 질의(1.006배)에서는 잡음 범위였다. SQL을 쓰지 않는 함수는 `PARALLEL_ENABLE`로 선언하면 커버링을 그대로 쓴다. 블록 단위로 좁히는 안은 스캔보다 먼저 끝나는 하위 질의(실체화되는 파생 테이블, CTE)만 가려내야 해서 놓치는 경로가 생기기 쉽다고 보고 미뤘다(사용자 결정 2026-10-11). 실제로 문제가 되는 사례가 나오면 다시 연다.
- 커버링은 스캔을 열 때 끄므로 Query Plan에는 `covered: true`가 남고 Trace Statistics의 인덱스 스캔에 lookup이 나온다.
- 스캔 도중 데이터를 바꿀 수 있는 새 경로(SP가 아닌 새 함수 등)를 더할 때는 이 판정에 함께 넣어야 한다. 넣지 않으면 페이지 복사 스캔이 그 변경을 놓친다.
- CBRD-27591(SP DML의 fixed scan 자기 래치 대기)을 fixed scan 끄기로 고치면, 그 문장은 이 결정에 따라 COPY 읽기로 간다.
- 용어: `CONTEXT.md`의 "페이지 복사 스캔", "문장 내 변경", "읽는 시점 의미".
