# 인덱스 범위 스캔의 리프 상한 판정은 게이트 없이 항상 켜진다 — "새 엔진 경로는 default OFF" 규칙의 예외

저장소 규칙("A new engine path is env-gated default OFF unless a ticket records a feature-specific exception")의 예외를 이 ADR 이 기록한다. 인덱스 범위 스캔이 범위의 처음 2키를 키마다 상한과 비교한 뒤, 리프마다 키를 비교하기 전에 그 리프의 마지막 키를 한 번 비교해 그 리프의 비교를 건너뛰는 경로(리프 상한 판정)는 env 변수·시스템 파라미터 스위치 없이 항상 동작한다(사용자 결정 2026-11-18).

이유:

1. **결과가 바뀌지 않는다.** 리프의 키는 정렬돼 있으므로 건너뛴 키의 상한 비교 결과는 비교했을 때와 같다. CTP sql 17821/17821, medium 975/975 가 이 경로가 켜진 optdebug 빌드에서 통과했다(run sql-20261118T073635Z-2155608).
2. **기본 OFF면 검증이 새 경로를 지나지 않는다.** CTP 는 기본 설정으로 돌기 때문에 꺼 둔 경로는 게이트에서 실행되지 않는다. 이 경로의 첫 결함(초기화하지 않은 `DB_VALUE`)도 CTP 가 잡았다.
3. **되돌리기 수단은 PR 이다.** 사양이 아니라 같은 비교의 횟수만 바뀐다.

## Considered Options

- **env 게이트 default OFF**(저장소 기본): 기각. 위 1·2.
- **판정 시작 기준을 범위당 64키로**(측정으로 짧은 범위 비용을 0 근처로 둔 값): 기각. 사용자가 2키를 택했다. 그 값에서 리프 하나 안에서 끝나는 3~300키 범위는 release `instructions:u` 기준 +0.6~4.0% 늘어난다.
- **리프마다 처음 2키를 키마다 비교**(2026-11-18의 첫 구현, PR 커밋 `8df41fb36`): 2026-11-20 기각. 참고한 인덱스 스캔 구현을 "블록마다 카운터를 2로 채운다"고 읽었으나 다시 읽어 보니 카운터는 스캔 시작·재개 때만 2로 채우고, 다음 블록으로 넘어갈 때는 끝 슬롯만 다시 구한다. 사용자가 그 방식으로 바꾸기로 했다(PR 커밋 `14b849cf5`). 긴 스캔의 상한 비교가 리프당 3번에서 1번으로 준다.
- **범위가 끝나는 리프에서 끝 슬롯 이진 탐색**: 기각. 키를 따로 읽어 비교하는 비용(범위당 약 1,500 명령어)이 커서 11~41키 범위가 범위당 1,700~2,800 명령어 늘었다(실측).

## Consequences

- 상한 비교 수는 범위 시작의 2번 + 리프마다 1번 + 범위가 끝나는 리프의 키 수다(int 기본 키 10만 키 스캔의 `btree_compare_search_key` 호출 200,048 → 1,474번, 트리 탐색 포함).
- 병렬 인덱스 스캔의 리프 워커(`leaf_slot_walker::check_key_in_range()`)는 이 판정을 쓰지 않는다.
