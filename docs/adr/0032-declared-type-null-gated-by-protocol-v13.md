# 선언 타입이 있는 NULL 과 EXECUTE 열 정보는 PROTOCOL_V13 확인으로 하위 호환을 지킨다

ADR 0031 은 드라이버, 브로커, 엔진이 모두 같은 버전이라고 가정하고 버전을 확인하지 않았다. 2026-10-27 그릴링에서 사용자는 "최신 드라이버 → 하위 CUBRID 가 가능해야 한다"며 이를 뒤집었다. 새 프로토콜 버전을 두지 않고, CBRD-27389 가 올린 PROTOCOL_V13 에 얹는다. V13 을 선언한 JDBC(9bd89eb)·CCI(79d0888) 커밋은 어느 릴리스 태그에도 없고, 이 기능도 11.5 에 함께 나가기 때문이다.

- 드라이버는 브로커가 V13 이상일 때만 선언 타입이 있는 NULL(타입 바이트 + 길이 0)을 보낸다. V12 이하 브로커에는 지금처럼 타입 없는 NULL 을 보내므로, 답과 열 정보는 그 서버의 지금 동작과 같다. 옛 게이트웨이 CAS(`cgw_set_bindparam`)가 타입 있는 길이 0 값을 값으로 읽는 문제도 이것으로 피한다.
- 브로커(CAS, CGW)는 드라이버가 V13 이상일 때만 EXECUTE 응답에 "열 정보 있음/없음" 표시를 싣는다. "있음"은 실행한 플랜의 열 정보가 PREPARE 응답과 다를 때이고 열 정보가 뒤따른다. 드라이버는 결과 셋마다 "있음"이면 받은 열 정보를, "없음"이면 PREPARE 열 정보를 쓴다. 그래서 양쪽 모두 핸들마다 지난번에 보낸 것을 기억하지 않는다. V12 이하 드라이버에는 지금처럼 값마다 타입 태그를 붙여 보내고, "NULL 타입 열에 NULL 이 아닌 값이 오면 막는다"는 규칙도 V13 이상 드라이버에만 건다.

## Considered Options

- **새 PROTOCOL_V14**: 기각. V13 이 아직 나가지 않았고 같은 릴리스에 나가므로 버전을 하나 더 쓸 이유가 없다.
- **같은 버전 가정 유지(ADR 0031)**: 기각. 새 드라이버를 옛 서버에 붙이는 응용이 깨진다.

## Consequences

- 혼합 조합(새 드라이버 + 이전 서버, 이전 드라이버 + 11.5 서버)을 지원 조합과 QA 호환 테스트의 합격 기준으로 둘지는 담당자에게 묻는다(APIS-1129, APIS-1130 코멘트).
- 11.5 전까지의 develop 빌드 가운데 V13 이면서 이 기능이 없는 빌드가 있다. 릴리스되지 않은 빌드라 지원 대상이 아니다.
