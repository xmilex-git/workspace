# 도메인 규칙은 현행 격자 + 게이트 확정 슬롯이다 (공통 타입 DOUBLE/VARCHAR 폴백 폐기)

호스트 변수·auto-param·세션변수 읽기·PL 인자(슬롯)의 도메인은 **현행 파서 격자와 서버 값 격자를 그대로** 두고 확정 시점만 옮긴다: 형제(컬럼·리터럴·CAST·선언 타입)가 있으면 컴파일이 형제 미러(소비자 도메인 우선, D-327-11)로 확정하고, 형제가 부류를 못 정하는 자리(형제 전부 슬롯·집계 인자·ENUM `±`·값 요구 함수·형제 없는 세션변수·게이트 의존 노드)는 서버 게이트가 바인드 값 타입으로 실행당 1회 확정한다. 지도 #312 차팅 때의 "애매하면 DOUBLE/VARCHAR 공통 타입" 은 채택하지 않는다 — 이전 캠페인에서 답을 바꾼 수정 270건이 전부 규칙 변경에서 나왔고(렛저 L-01·L-06), 정확 타입끼리 DOUBLE 로 가는 DB 는 PG·MySQL 에도 없다(#315 T1~T25). 결정 원문: #317 D-317-01~24, #327 D-327-01~11, #325 D-325-11·12, 정본 `docs/research/domain-pin-rule-table.md`(개정판 `dec15d2`, §7 확정).

## Considered Options

- **문맥 없는 슬롯에 DOUBLE/VARCHAR 기본형**(차팅 초안, MySQL 규칙과 동형): 기각. `? + ?` 접합·`enum + ?` 서수/이름·`addtime(?, …)` 오버로드처럼 값 타입으로 갈리는 현행 답이 바뀌고(P0 위반), ENUM 자리에서 서수 비교가 조용히 깨진 전례(L-06: 8행 vs 정답 7행)가 있다.
- **폭 보존 미러**(형제와 바인드 중 넓은 정수 타입): 기각. 행당 결정 0(P4)·형제 미러(P1)와 충돌 — 바인드 값이 플랜 도메인을 넓히면 플랜이 값에 종속된다.
- **B7 CHAR 컬럼 슬롯을 VARCHAR 로 미러**(D-317-04): 탐침 #319 에서 trailing-space 구분 때문에 1행 → 0행(silent) 이 드러나 **철회**(D-327-01). CHAR 미러 유지, VARCHAR 값의 원 값 유지는 게이트의 CHAR 변환기 손실 정책으로.
- **게이트 확정 식(`abs(?)`)을 바깥 형제로 미러 + 계획된 CAST**(collation 축의 방식): 타입 축에서는 기각(D-327-08). develop 의 "인자 하나라도 MAYBE 면 결과 MAYBE" 답이 바뀐다 — 게이트 의존 노드로 두고 G1 이 생산자 우선 순서로 격자를 1회 적용한다.

## Consequences

- 답안 변경은 규칙표 §7 확정 행만 허용(정수 형제 산술의 소수·날짜·비숫자 문자 바인드 -494, `? + n` 날짜 관용구 65곳, 넓은 바인드 축소, 표기 `1.0`→`1`, 공통값 미러, 세션변수 미러, 바인드 캐스트 반올림 → 게이트 손실 정책, 실행 중 세션변수 타입 변경 4건 D-325-12) — TC expected 갱신 + 릴리스 노트(`? + n` 날짜 산술은 `? + INTERVAL`/명시 CAST, D-327-09). 되돌리는 길: §7 행 하나를 되돌리는 것은 그 행의 컴파일 규칙 한 case 를 develop 으로 되돌리는 것이며 게이트·계획 구조와 무관하다.
- 실패 정책은 문맥별 현행(산술·함수 인자·리스트 컬럼은 `return_null_on_function_errors`, 대입 -494, 비교 keep; D-327-10, D-325-11). 한 `?` 의 다중 참조는 참조별 자리에만 NULL 이 들어간다.
- 두 격자(파서 C 행 / 서버 G 행)는 각 한 벌만 유지한다(P6). 서버 G 행 격자는 `query/` 전용 도메인 해석기 모듈(`domain_resolve`)로 모으고 클라이언트 헤더로 새지 않는다(D-318-07, D-323-02·15).
- 비직관 현행(§7 밖, D-317-15)·ENUM 형제 collation 결함(D-322-04)은 이 PR 이 건드리지 않는다(후속 #326 등).
